### v3实际改动与依据

- v2的PNG像素全部不透明，但IHDR仍为RGBA / hasAlpha=true。v3将同一排版结果无损编码为RGB PNG，去掉未使用的Alpha通道。通过逐像素检查确认原有各尺寸的RGB颜色完全一致；这消除了文件格式歧义，不声称已证明Safari一定依据Alpha标记套底。
- 旧ICO为32 /48 PNG内嵌帧，现代浏览器可以读取，不能称作损坏。v3提供传统16 /32 /48位图DIB帧、全不透明像素与AND遮罩，并使用新的favicon-v3.ico显式地址；小图标补16px，根路径同步。macOS系统sips能够识别ICO的48px最大帧；这不是iOS历史记录原生验收。
- 明确提供1024px纯品牌Open Graph图，不含网络地址或用户输入；五页三语的标题 / 描述沿用当前页面元数据。依据[Apple TN3156](https://developer.apple.com/documentation/technotes/tn3156-create-rich-previews-for-messages)提供清晰图像 / 高分辨率图标与服务端元数据，避免只能依赖预览器自行猜图。旧版未提供OG本身不是标准违规，此处是让预览取图更明确，不保证设备已保存的卡片立即重建。
- 所有新资源 / manifest使用v3地址，旧v2专用资源保留供已缓存页面引用；共享根回退更新。普通 / Apple原构图、Android安全区和品牌原图不变，不借本次重画角色、缩小导航图或加入离线服务。
- sharp0.35.5已是Next.js锁定的依赖，本次通过Bun显式列为生成工具的开发依赖。Bun重排部分hoist条目，实际包版本集合未变化，没有批量升级。第一次写本地Bun缓存被权限阻止，经允许的缓存权限重跑成功，原始记录在ops。
