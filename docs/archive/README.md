# 任务文档归档规则与索引

更新：2026-11-13。本文件规定后续每个任务的自动归档责任；它是执行任务时必须完成的步骤，不依赖用户再次提醒，也不是后台监听器、定时任务或新安装的服务。

## 文档入口与唯一职责

| 入口 | 维护内容 |
| --- | --- |
| [开发进度](../PROGRESS.md) | 当前阶段、任务状态、实际完成项、阻塞、下一步和任务归档入口；开发进度唯一维护处 |
| [路线图](../ROADMAP.md) | 产品范围、已选方案、结构、依赖、实施顺序与验收标准；不再复制任务当前状态表 |
| 根 AGENTS.md | 中文协作规则，要求执行者每次任务自动归档和同步进度 |
| docs/archive/ | 开发任务产生的说明、调研、决定、测试记录、截图与交付材料 |
| ops/archive/ | 运维任务产生的说明、服务器资料、部署记录、检查结果与日志；整个目录 Git 忽略 |

运维归档与开发归档必须分开。**整个 ops/ 都是本地运维资料目录，以 /ops/ 统一 Git 忽略**，包含日志、服务器信息、私钥、配置、历史辅助脚本和归档；不提交或上传任何子项。ops/README.md 仅为本地入口；已有机密仍在 ops/secrets，保留原名、不搬出忽略区。正式项目更新工具与部署配置规划在 scripts/geoip、deploy，不作为 ops 内容。

## 目录与命名

- 开发：docs/archive/<阶段>/<任务编号小写>-<英文摘要>/。
- 运维：ops/archive/<阶段>/<任务编号小写>-<英文摘要>/。
- 阶段用 m0–m9，沿用路线图已有 M1-01–M1-08 任务编号；新增任务先登记稳定编号。维护任务可用 M0-DOCS-01、M0-OPS-01 等，不伪装成应用实现完成。
- 目录和文件名用英文小写 kebab-case，文件内容默认中文。任务目录名一旦建立不随标题改写；同一任务多次会话继续更新原目录，不每轮复制一份。
- 每任务仅要求 README.md 入口；有实际内容才增加 design.md、testing.md、decisions.md、evidence/ 或 deliverables/，不预建全套空文件夹。
- 截图 / 输出按 YYYY-MM-DD-<英文说明> 命名。原始证据保留原文件名及内容；历史迁移时用任务入口记录原位置与文件哈希，不改原报告来制造新结果。

示例（规划路径，不代表功能已实现）：

```text
docs/
├── PROGRESS.md
├── ROADMAP.md
└── archive/
    ├── README.md
    └── m1/
        └── m1-04-ip-query/
            ├── README.md
            ├── testing.md      # 有实际测试记录时添加
            └── evidence/       # 有可公开证据时添加
ops/
└── archive/                     # Git 忽略
    └── m1/
        └── m1-08-deployment/
            ├── README.md
            └── evidence/
```

同一开发任务涉及运维时，两边沿用相同任务编号，分别记录职责与材料；进度页只说明运维结果 / 待验项和本地归档位置，不复制服务器清单、私人配置或未脱敏输出。公开文档不要建立必须依赖私有归档才能理解的交付结论；私有路径可用代码文本标明“仅本地”，不制造公开仓库的失效链接。

## 每任务自动执行流程

1. **开始时**：读取 AGENTS、PROGRESS 和 ROADMAP 对应条目，明确任务编号、授权范围和验收条件；在实际开始工作时建立任务目录及 README，更新进度为进行中。仅列计划不批量创建未来任务的空目录。
2. **过程中**：说明、决策与实际证据直接写入该任务目录。不同任务不混放，相关决定回写 ROADMAP；仅有信息变化时更新进度。临时测试数据与编译产物不当文档保留。
3. **阶段变化时**：已实现、已测试、已部署与用户确认分别记录；完成、待验、受阻或暂停均写真实状态和下一步。中断任务同样归档现有结果，不能因为未完成就不写。
4. **答复用户前**：归档本轮产生的必要文档 / 截图 / 报告，修复移动后的链接，同步 PROGRESS；核查文件清单、内容一致性、链接和机密排除，读回确认状态无误，再给出交付说明。
5. **收尾**：README 记明实际改动、验证方式及结果、未验证范围、遗留项与证据入口。未执行的测试必须标“未执行”，用户反馈与独立验证分开。归档是任务完成条件，不得将“稍后补文档”作为默认收尾。

不自动移动源代码、可执行测试、项目部署模板、品牌原图或凭据：项目代码仍在 src / tests / scripts / deploy 的既定位置；只有过程文档和应保留证据按本规则归档。不重建已删除的原型或设计资料，不将归档当作废纸篓。

## 任务 README 最小内容

```text
任务编号 / 标题：
所属阶段 / 类型（开发或运维）：
开始日期 / 最近更新：
当前状态：
目标与本次授权：
实际改动：
验证记录（方法、环境、预期、实际、证据）：
未验证 / 未完成 / 阻塞：
下一步：
相关路线图验收编号 / 文件入口：
```

未涉及的测试类型写“不适用”并说明原因；不可空填成“通过”。修正历史结论时保留原证据，追加更正及依据，不改写过去的原始输出。

## Git 与机密边界

- docs/archive 是开发文档归档，不等于自动提交；仍需按用户授权决定暂存、提交和推送。
- **/ops/ 已加入 Git 忽略，覆盖整个目录**，无需按子目录或文件类型枚举。后续日志、服务器信息、密钥和运维材料均留在该忽略区；不得通过重命名扩展名或把文件移到 docs 绕过。若已有跟踪文件，先核查再定点取消跟踪，不能删除本地资料；本轮原仓库没有跟踪文件，无需取消跟踪。
- 禁止用 git add -f 绕过运维 / 机密忽略；私钥、MaxMind 配置、真实 .env、机器指纹、原始私人日志不进入开发归档或公开构建材料。文档归档同样不授予发布 Git 或部署的权限。
