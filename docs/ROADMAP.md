以下规则已按 C01 确认；数据更新进程独立于 Next.js 请求处理：

1. **香港本机直连、官方工具。** 沿用原名 `GeoIP-raelfang.conf`，只读挂载给官方 geoipupdate；应用进程不需要访问下载凭据。持久数据目录独立于应用镜像，公开服务使用 443；没有新增 8443 的需要。
2. **一次任务、一个候选数据集。** 防止并发更新。检查三库的官方版本，仅下载有变化的库；变更库下载整份新文件，不是增量补丁。未变化的库沿用当前文件，候选始终包含 City / Country / ASN 三份完整文件。三库的发布日期允许不同，不强求它们同一天构建。
3. **在暂存目录校验。** 检查官方工具成功状态、文件类型、可读元数据、构建时间及文件哈希，运行固定 IPv4 / IPv6、公网 / 保留地址样本。可选国家或城市缺失不是文件损坏，注册国家不补成定位国家。格式错误、查询异常或工具失败均不得发布候选。
4. **三库作为一组切换。** 应用先打开并验证候选的三个读取器，再切换一个数据集引用；单次查询固定使用同一数据集。只改变磁盘软链接不能算应用已热加载。若用容器，挂载数据父目录，不依赖单个旧文件 inode 的绑定；读取器和缓存切换要在 M1 集成验证。
5. **没有变化就不切换，失败时保留当前有效数据。** 只有候选验收成功才替换；读者切换并待正在进行的请求结束后，清理旧文件和暂存区，不长期堆积数据库归档。首次初始化无数据时显示资料暂不可用，当前出口 IP 仍可显示。候选失败不导致半套新库被访问。
6. **记录真实版本与状态。** 保存每库构建时间、SHA-256、数据集标识、最近成功检查时间、最近实际变更时间及脱敏错误类别；页面不把检查时间当成数据发布时间。缓存按目标 IP 和数据集标识隔离，出口识别响应不进入共享缓存。
7. **故障处理与保留边界。** 日常失败在下一次每日检查重试；401 / 403 / 451 明确记录，当前任务不反复撞拒绝；429 尊重供应方退避。连续 72 小时未成功检查时显示更新异常；连续 30 天无法确认数据有效则停止地理查询，但仍提供基础出口。该 72 小时 / 30 天门槛是本项目已确认的产品策略，不是对条款的复述；许可证终止或已知数据必须删除时不能继续沿用。

官方推荐 MMDB 使用 geoipupdate；现行 GeoLite EULA 要求署名，并要求在新版发布后的规定期限内停止使用、清理旧版，不能以故障兜底为由无限保留旧库。上述更新失败策略应受其约束，正式公开展示及使用方式在上线前按适用条款核对，不额外开放 MMDB 原文件下载。[官方更新指南](https://dev.maxmind.com/geoip/updating-databases/) / [GeoLite EULA，页面标注 2026-02-12 更新](https://www.maxmind.com/en/geolite/eula)。M0 确认本身不代表部署；后续执行证据见 PROGRESS。

C05 / C06 的语言选择与共用网址规则：

- **优先级：本浏览器上次手动选择 → Accept-Language → 英文。** 简体 / 繁体语言标签按语言与书写体系匹配；不支持的偏好值忽略，不根据出口 IP 选择语言。三语首页均为 /，查询页均为 /ip?ip=...。
- 手动切换语言只更新偏好与界面；URL、当前目标、未提交输入、查询结果和状态保持不变。建议仅用第一方偏好 cookie 保存 locale，保存期 180 天作为实现默认值；不在 cookie 中保存 IP 或历史。最近查询在同一浏览器列表跨语言去重、可清空。
- 分享结果链接不携带语言，接收者按自己的保存选择 / 浏览器语言查看。页面刷新、前进后退仍恢复相同目标，不能切回错误语言或清空查询。Cookie 不可用时，本次切换仍应生效，但不承诺跨刷新保存。
- next-intl 使用请求级配置读取偏好和消息，不增加语言路径、语言子域、语言查询参数或自动语言跳转。此前前缀方案从未实施，不新增旧前缀兼容入口或重定向；/api、静态资源、健康检查及双栈端点同样不复制语言路由。[官方无独立语言网址方案](https://next-intl.dev/docs/getting-started/app-router#provide-a-locale)。
- 服务端首屏与客户端使用相同 locale，正确设置 HTML lang、Content-Language 和页面标题。个性化 HTML 不使用跨用户的共享缓存，避免 CDN 把一个人的语言发给其他人；原始 IP 数据缓存仍按本章接口与缓存分工处理。使用同一规范 URL，不把同一个 URL 伪装成三条不同语言的 hreflang 链接。
- M1-02 采用请求级 next-intl 与第一方 `IPINFO_LOCALE` 偏好 cookie；客户端切换只更新状态，不刷新路由。主题由 next-themes 保存到 `ipinfo-theme`，首次跟随设备。两页动态 HTML 返回 private / no-store；框架会重写 Vary，验收以实际禁止共享缓存为准。服务端 Content-Language 表示该次响应语言；当前界面切换同步 HTML lang 和标题，后续请求再使用已保存偏好。真实资料与历史按 M1-03 / 04 分别验收，当前状态见 PROGRESS。
- M1 验收包括三语正常 / 空 / 失败状态、繁体与英文长文案、浏览器语言匹配、手动偏好优先、刷新保留、共享链接接收方语言、切换不丢输入 / 结果 / 历史，以及不同访客之间不串语言。上述均为验收要求，实际执行范围与证据见 PROGRESS。

M1-07 补充约定见 [同内容坏库恢复](archive/m1/m1-07-integrated-acceptance/repair.md)：数据内容标识与物理代次分离，校验失败的当前目录不能因候选哈希相同而刷新为成功；修复文件先独立落盘，再原子发布可选 folder。旧状态兼容，先升级读取端再升级更新端。完整综合标准与实际边界见 [验收矩阵](archive/m1/m1-07-integrated-acceptance/acceptance.md)，用户视觉反馈来源单独记录。

M1-04 页面执行口径：提交时标准化单目标并使用原生 History API，URL 恢复与主动提交分开；请求使用 AbortController 和序号防止旧响应污染结果 / 历史，浏览器等待上限 12 秒。历史仅记录主动提交、手动重试或结果刷新成功的公共 IP，localStorage 键为 ipinfo-recent-queries-v1，最多十条标准化去重；URL 初次打开、刷新和前进后退只恢复结果，不重新写历史，保证清空后刷新不恢复旧条目。存储失败不阻塞查询，清空写入失败明确提示，不假报持久清空。界面保持原有 Neutral 与同字号 IP，实际测试见 M1-04 任务归档。

| A12 可操作性与成品视觉 | 导航、表单、菜单、详情、状态提示和焦点 | 键盘可完成查询、切换和关闭菜单；焦点可见，标签与状态可感知；保持紧凑层级、Neutral 默认基线与原始品牌素材。用户确认实际两页视觉；仅代码完成不算视觉通过 | 键盘 / 无障碍基础检查 + 真实页面截图 + 用户视觉反馈 |
| A13 数据不可用与运行边界 | 无 MMDB、损坏、资料服务不可用、未准备就绪与重启 | 出口 IP 取得后仍可显示；资料明确暂不可用且不造数据；健康检查能区分进程存活与资料未就绪；凭据和 MMDB 不进入客户端产物、日志或公开目录；应用无下载凭据读取权限 | 接口故障注入、生产构建产物 / 挂载检查 |
| A14 更新及切换 | 03:00 时区、无变化 / 失败 / 部分库错误、并发查询、阈值和清理 | 每天 Asia/Taipei 03:00 检查一次；避免重叠，错过后补一次。候选三库全验过才切换，不要求三库构建日期相同；单请求不混用切换前后读者，缓存同步失效；失败留仍有效数据，72h 提示、30d 按 C01 暂停资料且保留基础 IP，清理已不使用的旧文件 | 受控候选库与模拟时间，故障恢复回归；08 检查实际调度、权限和重启持久化。无变化不消耗重复完整下载 |
| A15 公网与既有业务 | 授权目标版本、域名 / 证书 / 入口、双栈 CORS、更新任务、数据持久化 | 主站同源 API、DNS-only v4 / v6 HTTPS 443 均可用；证书可信，真实客户端 IP 正确；更新和重启恢复正常；内部端口 / 凭据未公开，无新增 8443 要求，既有其他服务保持正常 | 获准部署后实际环境核查、发布前后服务对比、真实公网浏览器与请求证据 |
| A16 交付收口 | 实现、自动检查、本地浏览器、公网、视觉反馈和遗留项 | 每类证据分别归档；构建与适用测试通过，范围内阻塞项清零，视觉有用户反馈，公网关键路径通过后才标 M1 已上线。无部署授权 / 无网络条件分别记待部署 / 待验，不写成已通过；不自动进入 M2 | 路线图状态读回与脱敏证据索引 |

M1 完成分三道记录：**本地实现与验证完成 → 获准部署并公网验证通过 → 用户页面 / 交互验收确认**。前者不代表后者；若已发布但尚待用户最终反馈，保留“已上线，待用户验收”，不能写成整阶段完成。精确超时 / 限流数值在执行时固定并验证有界等待，不在当前文档虚构毫秒级性能承诺。

归档规则：本文件维护范围、顺序和标准；当前状态统一维护在 [PROGRESS](PROGRESS.md)。执行每项任务时，开发文档 / 测试证据自动归入 docs/archive/<阶段>/<任务>/；运维文档 / 报告归入 ops/archive/<阶段>/<任务>/，整个 ops 受 Git 忽略，含服务器资料、秘钥与日志。每任务使用 README.md 索引，有实际材料才建目录；答复前归档并同步进度是必须步骤。详见 [统一归档规则](archive/README.md)。

### M2：出口与浏览器检测

实施次序：先 M2-01 IPv6 就绪检测，复用已验证的双栈入口；其后分流、DNS / WebRTC 与环境信息按独立任务推进，不因启动 M2 批量创建空目录。

| 任务 | 范围 | 本项验收 |
| --- | --- | --- |
| M2-01 IPv6 就绪检测 | /ipv6 独立页，IPv4 / IPv6 端点与本次主站连接观测、HTTPS 请求耗时、独立取消 / 重试 / 全部重测；首页与导航提供入口，三语与主题沿用 | 三项独立、5 秒上限、取消与旧响应不污染结果；未确认不误报仅 IPv4 / IPv6；伪造头无效、无共享缓存 / 任意目标；真实双栈及具备条件的单栈验证，缺失环境明确；手机无溢出、切语言保留结果；不宣称原生网络或 ICMP 测速 |


- 分流：按分类查看目标出口，相同 IP 归组，识别同协议下的多出口，支持单项和全部重测。
- IPv6：IPv4-only、IPv6-only、双栈、实际采用协议、请求延迟与就绪说明。
- 泄漏：随机子域名的 DNS 解析器观测、WebRTC ICE 候选分类、出口对照与局限说明。
- 环境：浏览器、系统、UA、语言、时区、屏幕、触控、Canvas / WebGL 等可用指标，一致性结果及请求头视角。
- 首页检测卡片逐步接入；默认启动策略与展开方式保持简单，允许单项独立失败、取消或重测。

验收：在具备条件的 IPv4-only / 双栈、不同浏览器与代理模式下验证。跨域受限、mDNS 隐藏、超时和权限不足显示为相应状态，不能统一报“泄漏”或“网络异常”。观察结果和推断分开。

### M3：网络资料与查询工具

- DNS：A、AAAA、CNAME、MX、TXT、NS、CAA、HTTPS；境内外解析器对照、TTL、耗时与失败说明。
- ASN：持有者、前缀、上下游与路由关系；BGP 可视化、前缀 / 企业 / 注册地区历史与变动时间轴。
- Whois/RDAP：IP、IPv6、ASN、域名注册信息；来源、缓存时间与无记录状态。
- IP 地图：定位与多来源差异；IP 计算器支持约定的 IPv4 / IPv6 网段、掩码、范围和子网计算。
- UA 解析：用户输入 UA 的浏览器、系统和爬虫信息；查询输入扩展为域名解析与 ASN 跳转。

验收：使用已知域名、IPv4 / IPv6 网段、ASN 与注册信息样例核对；支持国际化域名与错误输入。DNS 差异不自动等同污染，BGP 关系和地理定位保留其数据边界。

### M4：风险数据与评分

- 多地理库对照；住宅 / 移动 / 商业 / 机房等网络类型、注册地与使用地对照及不确定状态。
- 展示各有效来源的代理、VPN、Tor、住宅代理、隐私中继、滥用、攻击、垃圾信息、服务器 / 自动化及黑名单信号。
- 原站显示的人机比例在来源具备时接入；没有数据明确标为未知，不制造比例。
- 定义 IPinfo.dog 自己的可解释评分、置信度与版本；保留来源明细、更新时间、命中 / 有效来源数和缺失处理。
- 场景适配覆盖 TikTok、Facebook、X、跨境电商、流媒体与 AI；同时记录评分历史，供后续轨迹与排名使用。
- 单家失效不拖垮查询；结果缓存、刷新、日额度与滥用限制有明确口径。

验收：正常 / 有风险 / 来源冲突 / 数据不足 / 来源超时都有案例；不能把未知写成安全。总分方向一致、可解释、同一规则版本可复算；不宣传等同平台官方判断。某个必需来源未接入时，该子项保持未完成或阻塞。

### M5：性能与节点

- 常用网站的浏览器请求延迟、采样与重测。
- 全球 Ping：目标 IP / 域名、地区筛选、探针位置、延迟、丢包、任务进度和配额。
- 带宽：明确点击启动、下载 / 上传 / 延迟 / 抖动、取消与耗流量说明。
- CDN：逐项浏览器直连，获取可读取的节点代码 / IP、城市、缓存状态与请求延迟；显示汇总和节点分布。

验收：区分浏览器 HTTPS 时间、远端 ICMP 与带宽，不混为同一指标。目标、探针、样本数、时间可追溯；CORS 或响应头不可读有原因；不能用服务器代测结果冒充用户浏览器出口。

### M6：服务专项

- Claude 专页组合其实际出口、地区、风险、泄漏与环境信息。
- AI 检测与平台检测：逐服务识别出口、地区 / 节点、风险、官方状态及综合解释；支持分类和重测。
- Cloudflare：命中节点、WARP、连接协议、网络等级对照、延迟、节点历史、环境风险；Turnstile 使用自己的站点配置和服务端验证。
- 服务状态：对接公开官方状态源，区分官方故障与当前用户链路问题。

验收：地区限制和风险阈值标注来源 / 口径 / 时间；“检测到出口”“地区参考可用”“实际业务成功”分开。验证码成功必须有服务端校验，未配置不能展示通过。外部服务不可读或没有公开状态页按实显示。

### M7：报告、卡片与内容

- 完整报告复制、结果链接、截图导出、信息纠错与反馈入口；完善首页卡片显示 / 隐藏设置。
- 动态 IP 信息卡：经典 / 信用卡 / 货币等类别，以及信息卡 / 签名条 / 徽章；主题、宽度、语言、标签和可用评分印章；预览与嵌入代码。
- 嵌入支持 Markdown、HTML、BBCode 与直接图片地址。说明图片代理可能使卡片显示平台服务器而非访客信息。
- 站内总查询、近期查询、分数分布、地区分布、网格地图、脱敏最近查询、全站 / ASN 排名与评分轨迹。
- 基础简体 / 繁体 / 英文框架和两页已按需求前移至 M1；M7 为本阶段的帮助与知识库、关于、品牌资料、联系、隐私说明与条款同步提供两种语言，其他功能随其各自阶段补齐翻译。内容按实际运行方式编写，联系渠道不擅自公开私人邮箱。
- 对首页观察到的广告 / 推广区域登记展示位置与开关；具体内容和广告服务在使用前确定，不将广告占位等同已经接入投放。

验收：截图 / 文本 / 链接与同一结果一致；动态卡片在直接访问及图片代理场景中行为可解释；统计基于真实数据而非预填数字，公开 IP 按约定脱敏。M0 应核实卡片类别的具体变体，不能仅以一个通用卡片代替全部功能。

### M8：账号与社交

- Google 登录采用 OpenID Connect 身份认证；GitHub 登录采用其 OAuth 网页授权流程。登录入口仅保留这两项，不建设邮箱验证码或本站密码登录。
- 首次成功授权创建本站账号；重复登录返回同一账号。使用本站用户 ID，并以提供方与其稳定用户标识关联身份，不能把可变的邮箱或用户名当作账号主键。
- 账号内支持主动绑定另一种登录方式，要求验证当前会话和待绑定的第三方身份。仅邮箱相同不自动合并账号；一个第三方身份不能绑定多个本站账号；解绑时至少保留一种有效登录方式。已有两个本站账号的数据合并另行确认，不自动执行。
- 资料、会话与退出、登录后返回原页面、取消授权和提供方不可用状态完整。仅请求登录所需的身份权限；GitHub 私有邮箱或邮箱缺失不导致账号混淆，不申请仓库等无关权限。
- 按所选认证库完成服务端身份校验、授权回调防伪与重放防护、适用的 PKCE / nonce 校验、安全会话与机密管理。具体实现随框架确定，不手写一套不必要的认证协议。
- 动态分享与讨论；大厅聊天、私聊、群聊。登录后页面的发布、回复、资料、群成员及历史等细节，在可核实时补入基线。
- 完成必要的成员权限、历史分页、断线重连、消息去重，以及举报 / 屏蔽和管理处理能力；这些是运行社交服务的工程要求，不冒称均已在原站观察到。
- 登录不依赖 SMTP 或邮箱验证码服务。两家的应用创建、回调配置与密钥接入在实施时落实，不视为本计划已经执行。

验收：分别实测 Google / GitHub 首次建号、再次登录、绑定 / 解绑、退出、拒绝授权、失败回调与失效会话；覆盖 GitHub 邮箱不可见或缺失、两个身份邮箱相同但尚未绑定、身份已绑定其他账号等情形。至少两个本站测试账号验证会话与消息隔离，私聊 / 群聊权限、离线 / 重连、重复发送及内容处理。原站社交内部范围仍待补查；登录方式按用户指定的替代方案验收。

协议参考于 2026-11-13 核对：[Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect) · [GitHub OAuth 网页授权](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)。上述账号绑定规则是本项目的设计约定，不冒称提供方自动完成账号合并。

### M9：逐项收口

- 对照第 4 节和 M0 固定的子项清单逐项复测；截图仅作证据，不代替操作验证。

## 6. 交付与进度规则

- 每阶段采用同一顺序：确认本阶段范围 → 实现 → 必要测试 → 本地真实浏览器验证 → 在授权环境部署 → 公网验证 → 归档任务文档并更新 PROGRESS。
- 未授权部署时记录为“实现 / 本地验证完成，待部署”，不把它写成已上线。
- 子项当前状态由 PROGRESS 统一维护，使用：待实现、进行中、待验证、已验证、待部署、已上线、已完成、阻塞；暂停仅在用户明确要求时使用。并记录实际环境与证据；外部依赖缺失不靠假数据补成通过。
- M0 的计划进度、开发实现、验证与上线分别统计。暂不使用主观完成百分比；若后续使用百分比，必须标明分母和验收口径。
- 前一阶段验收后再推进依赖它的阶段。可独立的工作允许调整顺序；方案变更在本文件记录，实际原因和未关闭项在任务归档及 PROGRESS 记录。
- 公共组件、检测适配器和数据模型由后续功能复用；不为每个专项页面另建一套不一致的查询、评分或检测逻辑。
- 必要的限流、密钥保护、错误日志与健康检查随功能建设；不强制重新注册用户已删除的 Sentry / UptimeRobot 等第三方产品。
